opus-5-5 vs sonnet-5-5 demo-todo opus-5-5

A is the safer foundation despite its larger change surface: server/src/routes/tasks.ts protects state transitions against concurrent writers, and client/src/api/tasks.ts protects detail caches against overlapping saves and stale reads. Its targeted concurrency and recovery tests exercise these protections, whereas B leaves those failure modes exposed.

correctnessopus-5-5 In server/src/routes/tasks.ts, A performs transitions inside an immediate transaction with a conditional status update; B reads the status and later updates it unconditionally, allowing concurrent processes to overwrite intervening transitions. A's useUpdateTask also cancels stale detail queries and merges only changed fields, whereas B replaces the entire cached task, potentially overwriting another concurrent save's result.
structureopus-5-5 A's client components and server domain module reuse shared/taskWorkflow, while B separately defines workflow states and transitions in client/src/domain.ts, client/src/api/types.ts, and server/src/domain/taskWorkflow.ts. A's db.ts applies versioned migration files transactionally; B embeds schema creation and ad hoc column migrations directly in openDb.
testsopus-5-5 A's TaskDetailPage.test.tsx explicitly holds an old GET response until after a save and verifies that it cannot restore the old title; B has no equivalent stale-response test. A's retry.test.tsx verifies that retries actually restore usable pages and member options, while several B retry tests only verify an increased request count against a fake API configured to keep failing.
scopesonnet-5-5 B implements the presentation with a substantially smaller client/src/styles.css and keeps toast handling within BoardPage. A adds a much larger styling system, a separate toast hook, and development-security-header and proxy helper modules with dedicated tests, increasing the change surface beyond B's narrower implementation.
opus-5-5 vs sonnet-5-5 invoice opus-5-5

A provides the safer foundation for financial operations: settlement/recover.ts explicitly reconciles uncertain payouts, and invoice/statusLog.ts commits status changes and their logs transactionally. B has valuable backend regression tests, but its settlement/create.ts recovery gaps, floating-point money calculations, and largely untyped frontend API outweigh that testing advantage.

correctnessopus-5-5 A's invoice/totals.ts uses BigInt fixed-point arithmetic, whereas B's invoice/money.ts calculates discounted and taxed amounts with floating-point division and an EPS adjustment. A's settlement/recover.ts also reconciles unknown payouts against Cobo and recovers interrupted submissions; B's settlement/create.ts saves its attempt record only after a payout error and suppresses failures saving it, leaving a crash or database-error window without durable recovery context.
structureopus-5-5 A supplies shared response types in api/types.ts and uses React Query for caching and invalidation; B's api/client.ts returns any for most resources and introduces a separate useFetch implementation. On the backend, A passes the database, configuration and clock through AppContext, while B's route and domain modules import a globally connected database and read configuration through process-global getters.
testssonnet-5-5 B's webhook/settlement.test.ts injects a status-log failure and verifies that both the settlement and invoice states roll back before a successful webhook retry; invoice/idempotency.test.ts similarly verifies that a completion-record failure does not repeat the operation. A adds substantial UI regression coverage, including InvoiceForm.test.tsx and PayerInvoice.test.tsx, but the supplied A changes contain no comparable backend persistence and transaction regression tests.
scopetie order disagreement: a / bB's SettlementConfirm.tsx retains a removed state and rendering branch without ever calling setRemoved, and InvoiceForm.tsx declares an unused MAX_CC constant. B's cobo/auth.ts additionally fabricates an ephemeral signing key and a dev-org-token fallback when credentials or OAuth fail; A's cobo/client.ts reports missing credentials or external failures instead of introducing those substitute authentication behaviors.
