# PRD: Personal To-Do Web App

## 1. Problem & Goal
Individuals need a lightweight place to capture tasks and track what's done
without signing up for an account. Ship a single-user to-do web app where a
person can add, edit, complete, delete, and filter tasks, with data persisting
across browser sessions. No accounts, no multi-device sync.

## 2. Functional Requirements

### FR-1 Add task
User can create a task with a required non-empty `title` and an optional
`dueDate`.
- AC-1: submitting a non-empty title adds the task to the list and clears the
  input; an empty/whitespace-only title is rejected with a visible message and
  no task is created.

### FR-2 Complete / reopen task
User can toggle a task between active and completed.
- AC-2: toggling a task flips its completed state, updates its visual style, and
  the change survives a page reload.

### FR-3 Edit task
User can edit an existing task's title and due date.
- AC-3: saving an edit updates the task in place; an edit to an empty title is
  rejected and the original value is kept.

### FR-4 Delete task
User can delete a task.
- AC-4: deleting a task removes it from the list immediately and it does not
  reappear after reload.

### FR-5 Filter tasks
User can filter the list by all / active / completed.
- AC-5: "active" shows only incomplete tasks, "completed" shows only completed
  tasks, "all" shows every task; the active filter is visually indicated and the
  visible count reflects the current filter.

### FR-6 Persistence
Tasks persist across browser sessions on the same device.
- AC-6: tasks added/edited/completed/deleted are still in the correct state
  after fully closing and reopening the browser.

## 3. Non-Goals
- No user accounts, authentication, or multi-device sync.
- No collaboration, sharing, reminders, notifications, or recurring tasks.
- No categories, tags, priorities, or sub-tasks in the MVP.
- No native mobile app; responsive web only.
