# PRD: Real-Time Group Chat Web App

## 1. Problem & Goal
Small groups need a simple place to talk in shared channels in real time. Goal:
ship a web app where registered users create and join public channels and
exchange text messages that appear instantly for all members, with presence,
timestamps, and history on channel open.

## 2. Users & Stories
- As a visitor, I want to register and sign in, so that I can participate under a
  stable identity.
- As a member, I want to create a public channel, so that my group has a place to
  talk.
- As a member, I want to join any public channel, so that I can take part in its
  conversation.
- As a member, I want to post a message and see it (and others') appear instantly,
  so that conversation feels live.
- As a member, I want to see who is online in a channel and when each message was
  sent, so that I have context.
- As a member, I want past messages to load when I open a channel, so that I can
  catch up.

## 3. Functional Requirements

### PRD-1 Account registration & sign-in
Users register with credentials and sign in to obtain an authenticated session.
- Acceptance: a new user can register and then sign in; an unauthenticated user
  cannot post messages or create channels and is prompted to sign in; duplicate
  registration is rejected with a clear message.

### PRD-2 Create public channel
An authenticated user can create a public channel with a unique name.
- Acceptance: creating a channel with a non-empty, unique name makes it appear in
  the channel list for all users; a duplicate or empty name is rejected.

### PRD-3 Join channel
An authenticated user can join any public channel.
- Acceptance: after joining, the user is a member, receives that channel's live
  messages, and appears in its member/presence list.

### PRD-4 Post & receive messages in real time
Members post text messages that are delivered to all connected members without a
manual refresh.
- Acceptance: a message posted by one member appears for every other connected
  member of that channel within ~1 second; empty messages are not sent.

### PRD-5 Presence
Each channel shows which of its members are currently online.
- Acceptance: opening/closing a channel connection updates the online list for
  other members within a few seconds; the list reflects only currently-connected
  members.

### PRD-6 Timestamps
Every message displays the time it was sent.
- Acceptance: each rendered message shows a human-readable timestamp derived from
  its server-recorded send time.

### PRD-7 Message history on open
Opening a channel loads its recent message history.
- Acceptance: on opening a channel, the most recent messages (newest at the
  bottom) are shown before/at the moment live delivery begins; an empty channel
  shows an empty state.

## 4. Non-Goals
- No private/direct messages, threads, reactions, or file/image uploads in the
  MVP.
- No message editing or deletion after send.
- No voice/video, typing indicators, or read receipts.
- No moderation, roles, or private (invite-only) channels.
